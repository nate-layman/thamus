Which do you trust more: someone who remembers everything, or someone who can look up the answer to anything?

Thamus would say the first. You have just watched five arguments, and none of them settles it. Before you answer, decide what a person has to carry in their own head to tell whether what came back is right.

  • What did the person have to already know to catch the memory answer when it was wrong?

Workshop key

The ways ask a language model, and that needs a key. In the workshop, scan the QR code or open the short link and the key is loaded for you. Otherwise paste one here.

How the key is handled
  • Tab-scoped. The key is held in sessionStorage, which belongs to this browser tab. It clears when the tab closes and is never written to disk.
  • Static site. This page is served as files from GitHub Pages. No server here stores or sees your key.
  • Sent only to the model’s gateway. A key starting with mr2_ goes to the University of Idaho’s MindRouter through the AI4RA lakehouse proxy. Any other key is treated as a Google Gemini key and goes to Google. The eCFR lookup, the web search and the vector database need no key at all.
  • URL stripped. A key that arrives as ?key= is read once and removed from the address bar.
  • Facilitators: pre-fill by sharing a link to this page with ?key=YOUR_KEY appended. Mint a workshop key and revoke it afterward.

The story

In Plato’s Phaedrus, Socrates tells a story about an Egyptian god named Theuth, the inventor of number, geometry, astronomy, and letters. Theuth brings his inventions to Thamus, the king, and argues for each one. When he comes to writing he makes his strongest claim:

This will make the Egyptians wiser and give them better memories; it is a specific both for the memory and for the wit.

Thamus is not persuaded. The inventor of a thing, he says, is not the best judge of what it will do to the people who use it. Then he delivers the verdict that has followed writing ever since:

This discovery of yours will create forgetfulness in the learners’ souls, because they will not use their memories; they will trust to the external written characters and not remember of themselves. The specific which you have discovered is an aid not to memory, but to reminiscence, and you give your disciples not truth, but only the semblance of truth; they will be hearers of many things and will have learned nothing; they will appear to be omniscient and will generally know nothing; they will be tiresome company, having the show of wisdom without the reality.

Plato, Phaedrus 274c to 275b, in Benjamin Jowett’s translation.

The paradox

Thamus warned that writing would ruin memory. He is remembered only because Plato wrote him down. Socrates, who tells the story, wrote nothing. So the dialogue does to Socrates what Plato does to Thamus: a warning against the written record, preserved for twenty-four centuries by nothing but the written record.

The same tension runs through every tool that lets us reach for stored information instead of holding it ourselves: writing, then libraries, then search engines, and now language models. The costs Thamus named are real. So are the benefits he dismissed. The question is never whether to reach for the record. It is who should reach for it, when, and what they must still carry in their own head to judge what comes back.

What it means for a machine

Thamus assumed that memory was the reliable thing and the record was the threat. For a language model it is backwards. Its memory is an enormous, averaged, frozen impression of everything it read, up to a date after which it read nothing. Ask it for the de minimis indirect cost rate and it will tell you ten percent, because that was the rule in most of what it read, and it will not tell you that the rule changed to fifteen percent on October 1, 2024. It is Thamus’s learner exactly: a hearer of many things, appearing omniscient, generally knowing nothing about today.

The remedy is the one Thamus refused. Give the model the written record and let it be reminded. For a machine, Thamus’s flaw is the feature: a model that is reminded is a model that can be checked.

How it works

This is a static page on GitHub Pages. There is no server of its own. Each way runs in your browser and calls out only for what it says it calls out for. Every way asks the same model, at temperature 0, with one system prompt and one message; open What the model was handed under any answer to see exactly that.

  1. Memory. The question alone. The model answers from training.
  2. Pasted text. Whatever you put in the box, and nothing else. This is the oldest form of context: the person does the reading and hands the model the page. It is also how most people actually use a chat window. The two fill links fetch the same paragraph of 2 CFR 200.414 as it stands today and as it stood in 2023, so you can see the model answer faithfully from either.
  3. Web search. The question, as typed, goes to a SearXNG metasearch on the AI4RA MCP server (Google, Bing, DuckDuckGo, Brave and others merged). The model gets eight titles, addresses and snippets. No page is read in full.
  4. Vector database. A build script cut 2 CFR 200 into 1,103 passages, one per paragraph or defined term, and embedded them with a small sentence-embedding model (all-MiniLM-L6-v2). Your browser loads the same model once (about 23 MB, then cached), embeds the question, ranks every passage by cosine similarity, and hands the top four to the model. This is retrieval-augmented generation as most products do it, and the index is as current as the day it was built.
  5. Live eCFR lookup. The model turns the question into two or three search words. The AI4RA MCP server’s eCFR tools search 2 CFR 200, fetch the top section, and when the section is long, the model picks the one paragraph to read. The model answers from that paragraph, with a pinpoint citation and the date of the text in force. It changes when the regulation changes, not when the model does.

Ways not on this page

  • Structured data over SQL. When the record is a table rather than prose, the model should write the query and let a database compute the answer. Data Crawler Carl does that for any CSV, in the browser, and is the sixth way in the workshop.
  • Files in reach of a local agent. Tools that run on your own machine, such as Claude Code, Cursor or Copilot, let you name a file with @path/to/file and the agent reads it into context. Same idea as the paste box, with the reading done for you, and the same obligation: you still have to know whether that file is the governing one.
  • Long context. Paste the whole of 2 CFR 200 and ask. It fits in some models’ windows now, at a cost in time and money per question, and the model still has to find the paragraph.

What leaves your browser

  • Your question and the retrieved text go to the model’s gateway: the University of Idaho’s MindRouter through the AI4RA lakehouse proxy with an mr2_ key, or Google with a Gemini key.
  • Your question goes to the AI4RA MCP server for the web search and the eCFR lookup. The server keeps no keys and logs none.
  • Nothing leaves for the vector database step. The embedding runs in your browser.

Source, build scripts and the index are on GitHub. The MCP server is ai4ra-mcp.
